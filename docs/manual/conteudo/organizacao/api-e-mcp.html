Para que serve

Em API Tokens o Administrador cria uma chave de acesso. Esta página mostra o que fazer com ela: como um outro sistema — o seu site, um ERP, uma automação, ou um agente de IA que não é o do ZapSales — conversa com o seu ZapSales. É um texto para quem vai fazer a integração; se você não programa, entregue esta página junto com a chave a quem vai.

Há dois caminhos, e os dois usam a mesma chave:

Quem tem a chave age na sua empresa.

Trate-a como uma senha: não a coloque em endereço de internet, em código público nem em mensagem de chat. Se vazar, revogue na hora e crie outra.

Como mandar a chave

A chave tem o formato zps_<8 caracteres>_<segredo> e vai sempre num cabeçalho da requisição:

Authorization: Bearer zps_…

Nunca na parte do endereço (depois do ?): endereços ficam gravados em registros de servidores e vazariam a chave. O ZapSales guarda só uma impressão digital da chave, nunca o texto, e por isso o texto completo aparece uma única vez, na criação.

O que a chave pode fazer

O que a chave permite é decidido na criação, pelos escopos (veja a tabela em API Tokens). Dois escopos mandam no MCP:

  • mcp:read — o agente externo pode ler o CRM (ferramentas de consulta).
  • mcp:write — o agente externo pode agir (ferramentas que gravam ou enviam).

Sem role:manager, a chave age com o papel de Atendente; com ele, vale como Gerente (necessário para criar e atribuir). Mesmo com a chave, o papel manda: uma ferramenta que exige Gerente não funciona numa chave de Atendente.

Ligar um agente de IA (MCP)

O MCP é um jeito padrão de dar “ferramentas” a um agente de IA. O ZapSales responde nele pelo endereço https://SEU-DOMINIO/api/mcp, pelo transporte Streamable HTTP, sem guardar sessão entre uma chamada e outra (cada requisição é independente). No cliente MCP do agente, cadastre:

  1. o endereço acima;
  2. o cabeçalho Authorization: Bearer zps_… com a chave que você criou (com mcp:read, e mcp:write se ele puder agir).

As ferramentas que o agente enxerga dependem da chave e da empresa: o catálogo muda conforme o papel, os escopos e os módulos ligados na instalação (por exemplo, as ferramentas de Honorários ou de dados externos só existem onde esses recursos estão ligados). O agente as descobre sozinho, pedindo a lista ao próprio servidor MCP.

Isto é diferente do agente do ZapSales.

Aqui o agente é de fora e usa o ZapSales como ferramenta. O contrário — um agente do ZapSales que usa um servidor MCP de outra empresa — está em Servidores MCP.

Se a empresa estiver suspensa, a chave ainda abre o endereço, mas o servidor só deixa responder o que é de privacidade (LGPD): nunca se bloqueia o atendimento de um pedido do titular dos dados.

Chamar a API REST

As rotas ficam em https://SEU-DOMINIO/api/v1/…. O programa que chama usa a chave no cabeçalho Authorization; as telas do sistema usam o login da pessoa. Nem toda rota aceita chave: a habilitação é feita rota por rota, conforme cada integração precisa, e a lista cresce com o tempo. Hoje aceitam chave, entre outras:

  • Mensagens e conversas: /api/v1/messages (enviar), rascunhos de conversa (/api/v1/conversations/{id}/drafts), envio de mídia em conversa e em nota, e abrir conversa com um contato (/api/v1/conversations/open-with-contact).
  • Contatos e negócios: /api/v1/contacts e /api/v1/leads/{id}.
  • Agenda: /api/v1/agenda/agendamentos e /api/v1/agenda/tipos.
  • Agentes e follow-ups: /api/v1/ai/agents (e suas versões) e /api/v1/ai/followup-flows.
  • Prospecção: /api/v1/prospecting.

Uma rota que ainda não aceita chave responde “não autorizado”. Se a sua integração precisa de uma rota que falta, peça a quem mantém o sistema para habilitá-la: o projeto converte as rotas que cada integração precisar, em vez de criar uma API paralela para cada cliente — uma rota habilitada serve a todo mundo.

As regras de toda resposta

AssuntoComo é
FormatoJSON, com nomes em snake_case (palavras separadas por sublinhado), datas em ISO-8601 no horário UTC e identificadores no formato UUID.
Sucesso{ "data": …, "meta": { … } }. Em listas, meta traz o cursor para a página seguinte e se há mais itens.
Erro{ "error": { "code": "…", "message": "…", "details": … } }. O code é um nome estável que o seu programa pode testar.
DinheiroEm centavos (um número inteiro), mais a moeda no padrão ISO-4217 (BRL, por exemplo). R$ 12,50 vira 1250.
PáginasPor cursor: o meta devolve um texto opaco; mande-o de volta para pedir a página seguinte.
RastreioToda resposta traz o cabeçalho X-Request-Id. Guarde-o: é o número que a equipe técnica usa para achar a chamada na Auditoria.
Limite de usoOs cabeçalhos X-RateLimit-* dizem quantas chamadas restam. Ao estourar, a resposta é 429 com Retry-After (quantos segundos esperar).

Repetir uma chamada sem duplicar (Idempotency-Key)

Redes falham, e o seu programa pode precisar repetir um pedido sem saber se o primeiro chegou. Para rotas que criam algo, mande um cabeçalho Idempotency-Key com um UUID novo por operação. Se o mesmo pedido chegar de novo com a mesma chave, o ZapSales devolve o resultado do primeiro em vez de criar de novo (o recibo vale 24 horas). Só algumas rotas de criação leem esse cabeçalho (entre elas o envio de mensagens e a criação de agendamentos); nas demais ele é ignorado.

O que fica registrado

Criar e revogar chaves ficam na Auditoria, e cada mudança feita por uma chave também é registrada, com o número do X-Request-Id da chamada.
